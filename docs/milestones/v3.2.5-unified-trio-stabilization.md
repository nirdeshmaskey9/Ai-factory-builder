Title: v3.2.5 — Local Trio Auto‑Stabilization (Unified Ollama Daemon)

Summary
- Consolidated Strategist/Memory/Executor under a single Ollama daemon at OLLAMA_HOST.
- Switched to model-based addressing; removed multi-port assumptions.
- Added exponential backoff to health checks (10s, 20s, 30s) with pytest fast-path.
- Simplified advisor health verification and embedded trio health in /factory/info.
- Trio manager refactored to monitor models only (no subprocess management).

Rationale
- Reduce flakiness from multiple daemons and port contention.
- Simplify configuration and startup behavior for local development.

Regression Notes
- Health checks use /api/version then /api/generate with prompt "ping".
- Under pytest, retries are reduced and sleeps are skipped to avoid slowness.

Verification
- /advisor/trio_health returns all three roles with healthy status when Ollama responds.
- /factory/info includes local_trio_health populated via advisor_service.verify_local_health().
